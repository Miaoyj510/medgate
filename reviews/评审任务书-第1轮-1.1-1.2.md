### 3. 评审重点清单（按优先级）

**A. 正确性缺陷（阻断项候选）**
1. 导入器：表头别名映射是否覆盖真实医保目录 Excel 的写法；日期解析是否会把「2026年1月1日」「2026/01/01」等写法漏掉；BOM 处理是否可靠（`utf-8-sig`）。
2. 重复判定：业务唯一键是否正确包含 `catalog_version`（同名同剂型**跨版本必须不算重复**）；重复行的报错行号是否指向正确行。
3. 限价语义：`price_public=False` 时是否真的不落任何价格值；文件里给了价格但标「不公开」时是否只告警不覆盖；`price_public` 缺失时的默认是否合理。
4. 校验分级：哪些是 error（不入库）、哪些是 warning（入库但需人工关注），分级是否会造成脏数据入库。
5. 日期倒置、必填缺失、非法甲乙类的判定是否都有对应测试。
6. `ensure_sqlite_dir()`：相对路径、`sqlite:///:memory:`、Windows 绝对路径、带盘符路径是否都正确处理。
7. `session_scope()`：异常时是否回滚、连接是否泄漏、嵌套使用是否安全。
8. CLI 退出码语义：有异常行时返回非零，是否会让 CI/脚本误判；`catalog-stats` 的「限价不公开条数」在 SQLite 下是否返回 `True` 而不是数字（此前修过一次，确认没退化）。

**B. 与 PRD 红线的符合性（阻断项候选）**
对照 `PRD-医保智能审核与处方前置Agent平台.md`：
- FR-CAT-02：目录走确定性查询，**不进向量库**——本轮是否引入了任何向量检索依赖或相似度兜底。
- FR-COST-03 / HB-2：限价不可得时必须输出「限价不可判定」，**不得估算**。
- NFR-01：线索四要素（规则编号、依据原文、出处、版本三元组）缺一即丢弃——本轮的数据结构是否为此留好了位置。
- NFR-03：版本三维（省份 × 就诊日期 × 年度）——表结构能否支撑 1.3 的解析，有无字段缺失或语义歧义。
- 11.3 / PV-5~PV-9：凭据不出现在日志、摘要、异常栈里；`.env` 不入库。
- 9.4 双库语义边界：目录侧与说明书侧的数据是否已物理隔离（本轮只应有目录侧）。

**C. 安全与合规**
- `.gitignore` 是否覆盖 `.env`、`.venv/`、`data/`、`.testtmp/`、日志；用 `git status --ignored --short` 实际核对有没有漏网的敏感文件。
- `config.py` 有没有把密钥写进任何可被打印的对象（异常信息、`public_fingerprint()`、`repr`）。
- 种子数据里是否混入了真实患者信息、真实目录价格或不该公开的商标准入数据。
- 异常处理是否会把数据库连接串、路径等内部信息暴露到用户可见输出。

**D. 测试质量**
- 断言的是**行为**还是实现细节？有没有「改了实现就假失败」的脆弱断言。
- 缺哪些边界：空文件、只有表头、未知表头列、同一行多次导入、并发导入、含空行/注释行的文件、超长字段、Unicode 药品名。
- `test_import_reports_counts_and_invalid_rows` 里的数字（24 / 21 / 3 / 1）是否与 `seed/catalog_sample.csv` 实际内容一致——**行数变了但断言没改，是典型的静默失效**。
- 用例之间是否互相污染（配置单例缓存、引擎复用、临时目录清理）。

**E. 仓库与工程**
- `scripts/verify.ps1` 在**干净环境**（删掉 `.venv`）下能否跑通；`verify.sh` 与 `ci.yml` 的步骤是否与 `verify.ps1` 等价（Windows 与 Linux 不一致 = CI 假绿）。
- CI 是否覆盖了 Windows 差异；`.github/workflows/ci.yml` 的 `on:` 触发范围是否正确。
- `WORKFLOW.md` 描述的流程与实际脚本行为是否一致（目录名、分支名、命令）。
- 文档与代码的一致性：`开发进度.md` 里声称的测试条数、文件清单、行为描述是否与代码对得上。
