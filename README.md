# MedGate · 医保智能审核与处方前置 Agent 平台（双闸门）

面向**医院医保办**与**药房前置审核**场景的双闸门前置核查平台。

> **第一道闸门核「钱」**：费用明细与医保目录、限价、支付范围是否对得上。
> **第二道闸门核「药」**：配伍禁忌、剂量异常、适应症是否越界。
> **系统只出线索与依据，结论由药师与医保办给出，全过程留痕可回放。**

本仓库是**求职作品集**项目：一份完整的 PRD（14 章、42 条 FR + 19 条 NFR 编号化）+ 可运行的实现工程。

## 为什么做这个项目

2024 年 11 月国家卫健委《卫生健康行业人工智能应用场景参考指引》（国卫办规划函〔2024〕420 号）列出 84 项场景，其中医疗服务管理领域下分设**医药服务**与**医保服务**两个子域 [1]——本项目的两道闸门正好分别落在第 16/17 项与第 19 项，这是「两套知识库必须分开」的政策依据。

现实中的缺口很清楚：

| 现状 | 缺什么 |
| --- | --- |
| 国家平台：日均处理智能审核案例超 2000 万件、准确率 92% 以上 [3]，2024-09 起覆盖所有统筹地区 [4] | 能力在**结算后与监管侧**，医院开方前用不上 |
| 院端：已有医院跑出可复制结果（处方合格率 75%→95%、拦截率 16.61%、平均审核 ≤45 秒）[15][16] | 多为单点规则，缺**版本治理**与**双岗权限闭环** |
| 规则：两库 88 类规则 + 24.7 万条知识点按批公开 [5][9] | 规则是「文件」不是「可判定条件」 |

**本项目补的就是中间那一层**：规则可判定化 + 版本可治理化 + 双岗签核化 + 全程可回放。

## 不可协商的五条设计纪律

1. **判定在本地规则引擎**，大模型只做要素抽取、归类与依据说明。
2. **目录走确定性查询，不进向量库**；费用侧与用药侧**不共库**——目录的「限定支付范围」回答「医保付不付」，说明书的「禁忌」回答「能不能用」，混库会把支付政策误当医学结论。
3. **线索必须带四要素**：规则编号、依据原文、出处、版本三元组，缺一即丢弃并计数（幻觉率 = 0）。
4. **版本键 = 省份 × 就诊日期 × 年度**，解析不唯一即硬阻断，不得「取最新」兜底（目录版本错用率 = 0）。
5. **结论权在双岗**：费用侧医保办签、用药侧药师签，互斥不可代签；单岗不得直达归档。

## 关键指标口径（公开对标 vs 自建目标分列）

| 指标 | 公开对标 | 本项目自建目标 |
| --- | --- | --- |
| 事前提醒接入率 | 全国 71%（三级 92% / 一级及以下 64%）[6] | 试点机构 100% 接入 |
| 拦截率 | 16.61%（云梦县，2026 年 1—7 月）[16] | 观察带 12%—18% |
| 处方合格率 | 75%→95%（临泽县）[15] | 试点基线 +5 个百分点 |
| 幻觉率 / 越权召回率 / 目录版本错用率 | 未找到可比公开口径 | **均为 0** |

> 金额与比率**不可跨口径混用**：「智能审核准确率 92%」属医保侧审减口径，「拦截率 16.61%」属院方药学口径。

## 合规声明

- 本产品**不做**自动拒付、自动扣款、「AI 认定违规」、AI 诊断与处方生成——处方须由接诊医师本人开具（《互联网诊疗监管细则（试行）》第二十一条 [21]）。
- 生成内容须显式 + 隐式标识，并完成算法备案与安全评估 [23][24]。
- 生产形态为**院内私有化**，数据不出院；出域仅限白名单字段并逐次留痕。
- 仓库内的目录、编码、说明书与评测数据**均为脱敏或合成示例**，不是真实医保目录或药品数据；接入真实数据前须核实各数据集的许可条款。
